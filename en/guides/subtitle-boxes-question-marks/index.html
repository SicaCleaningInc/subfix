Why Subtitles Show Boxes or Question Marks (and How to Fix It)

Updated: 2026-11-18

Broken subtitles come in three flavours: random symbols (mojibake), boxes, and question marks. They have different causes, so identify which one you have first.

Symptom 1: Random symbols like "ÖÐÎÄ" or "銝剜?"

This is a classic encoding error: the subtitle was saved as GBK or Big5 but the player read it with a different encoding. The text is still there and can be fully restored.

Fix: the Garbled Subtitle Fixer detects the original encoding and converts it to UTF-8. For Japanese or Korean, use the Japanese & Korean fixer.

B

Symptom 2: Boxes "□□□"

Boxes usually mean the font is missing those characters. The encoding is fine, but the player's font has no Chinese, Japanese or Korean glyphs.

Fix: choose a CJK font in the player's subtitle settings. In Kodi, set the interface font to Arial based (see the Kodi guide).

C

Symptom 3: Question marks "???" or "锟斤拷"

This usually means the file was already damaged by an earlier conversion: someone opened it with the wrong encoding and saved it, replacing the original characters.

The original text is gone and no tool can fully restore it. Re-download the original subtitle if you can. If only part of the file is damaged, the fixer will recover what it can.

D

Prevent it from happening again

  • Always save subtitles as UTF-8.
  • Don't save subtitles as "ANSI" in old versions of Windows Notepad.
  • Use a player font that supports Chinese.

FAQ

Can question marks "???" be turned back into Chinese?

Usually not. The original characters were replaced when the file was saved with the wrong encoding. Find the original subtitle instead.

What does "锟斤拷" mean?

It is a classic sign of text that was converted between encodings incorrectly and then saved. The original characters are lost.

Why do I see boxes only for some characters?

The font covers common characters but not rare ones. Switch to a font with full CJK coverage, such as Noto Sans CJK.

How do I stop this from happening?

Always save subtitles as UTF-8, and don't re-save a file that already looks garbled. See subtitle encoding explained.
