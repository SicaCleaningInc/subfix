Fix Chinese Subtitles in Plex, Jellyfin and Emby

Updated: 2026-11-16

Home media servers are great until Chinese subtitles turn into gibberish, empty squares (□□□) or simply don't show up. These are three different problems with three different fixes. Work out which one you have first.

Fix 1: Convert the subtitle to UTF-8

Older Chinese subtitles are usually saved as GBK (Simplified) or Big5 (Traditional). Media servers and their apps generally expect UTF-8, so these files appear as gibberish on some or all devices.

  1. Open the Chinese subtitle encoding fixer and drop in the subtitle files — a whole season at once is fine.
  2. Check the preview, keep "Add BOM" ticked, and download. The file name stays the same.
  3. Replace the old files in your library folder.
  4. Refresh the metadata for that title (in Plex: "Refresh Metadata"; Jellyfin and Emby have an equivalent refresh option) so the server re-reads the subtitle.

Japanese (Shift-JIS) and Korean (EUC-KR) subtitles have the same problem — use the Japanese & Korean fixer.

B

Fix 2: Empty squares — add a Chinese font

Squares mean the text is correct but the device drawing it has no font containing Chinese characters. This most often affects ASS subtitles, which are rendered with fonts supplied by the server or the app.

Jellyfin

  1. Download a font that covers Chinese, such as Noto Sans CJK (OTF format works well).
  2. Put it in a folder the Jellyfin server can read.
  3. Go to Dashboard → Playback → Transcoding, enable fallback fonts and set the fallback font folder path to that folder.

The web client uses these fallback fonts to render ASS subtitles. Users on Roku report also needing to enable "Use Fallback Font Across App" in the Roku client settings, and keeping only one font (under about 5 MB) in the folder, because the client uses the first font it finds.

Plex and Emby

Some Plex and Emby clients — especially web players and Apple devices — have trouble with Chinese ASS fonts. Two reliable workarounds:

  • Convert ASS to SRT with the ASS to SRT converter. SRT is rendered with the client's own fonts, which avoids most font problems (you lose styling).
  • Update the app: several Apple-device font issues were fixed in app updates. See Chinese subtitles on Apple TV, iPhone and Mac.
C

Fix 3: Subtitle doesn't appear — check the file name

Plex only picks up external subtitles that follow its naming rules: the subtitle must have the same name as the video, followed by a language code and the extension. The language code is a 2-letter ISO 639-1 or 3-letter ISO 639-2/B code. For Chinese, that means zh or chi:

Movies/Spirited Away (2001)/Spirited Away (2001).mkv
Movies/Spirited Away (2001)/Spirited Away (2001).zh.srt
Movies/Spirited Away (2001)/Spirited Away (2001).en.srt
Movies/Spirited Away (2001)/Spirited Away (2001).en.forced.srt

Plex only recognises certain extra tags such as forced and sdh; an unknown suffix like .zh.mysubs.srt may be silently ignored. Jellyfin and Emby use a very similar name.language.srt pattern, so the same naming works across all three.

After renaming, refresh the metadata so the server rescans the folder.

FAQ

Why do subtitles work in Plex on my computer but not on my TV app?

Different Plex apps render subtitles differently. Some TV apps lack Chinese fonts or can't read non-UTF-8 files, so the server may need to burn the subtitles in, which also uses more CPU.

Does Plex need a Plex Pass to show subtitles?

No. External SRT subtitles work on the free plan.

Jellyfin shows the subtitle but in the wrong language label. How do I fix it?

Add a language tag to the file name, such as .zh.srt, then refresh the item's metadata. See subtitle file naming.

Should I convert all my subtitles at once?

Yes, if you have many legacy GBK or Big5 files. The fixer takes multiple files and downloads them as a ZIP.
